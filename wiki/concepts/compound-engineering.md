# Compound Engineering（复利工程）

**一句话**：衡量一次工程工作的标准不是「这次做完没有」，而是「做完之后，下次做同类事情会不会更容易」。复利工程把每次解决问题时学到的规则、坑和范式沉淀成可复用资产，把单次 AI 产出变成组织级的可复用记忆，用来反转「代码库越做越慢」的趋势。

## 要点
- **主循环 `Plan → Work → Review → Compound`**，杠杆集中在两头：
  - Plan：先把方向、约束和实现意图讲清楚；
  - Compound：把这次学到的规则、坑、范式沉淀下来。
- **可沉淀的三类资产**：项目规范与约束、历史问题的解法、可复用的 Skill 或脚本。
- **三件东西要同时存在**：启动必读的规则、历史问题归档、按需调用的 Skill 文件。少一个，复利就出不来。
- **缺了 Compound 的后果**：团队反复为相似问题重新补 prompt、重新讲背景、重新踩同样的坑。
- **每个任务都应该改进「操作系统层」**：卡在上下文上，就改进记忆；同一个错误犯了两次，就把它变成规则。能胜出的系统不是写代码最多的 Agent，而是能从每个任务里**安全地学习**的系统。
- **复利会过期**：沉淀物同样编码着对当时模型局限的假设，模型变强后要修剪。

## 怎么做 / 为什么

### 沉淀物的强制力梯子
一条经验可以落在不同强制力的位置上，复利工程的日常动作就是判断它该落在哪一级：

| 层级 | 形态 | 特点 |
|---|---|---|
| 记忆 / 文档 | 项目文档、`CONTEXT.md`、ADR、历史问题归档 | 可被读取，不保证被用 |
| Skill | 按需加载的流程 | 匹配到场景才触发 |
| Rule | 入口文件里的常驻规则 | 每次都在上下文里 |
| Hook / linter | 确定性检查与拦截 | 不依赖模型「记得」 |

经验在梯子上的迁移也有规律：零散观察先积累成候选模式，被多次确认后聚合成 Skill，被多个 Skill 反复引用的内容再蒸馏成 Rule；review 反复发现同一类问题，就提升为 rule 或 linter。梯子本身就是约束的强制分层（Rule Enforcement Layers）。

### 哪些东西算复利资产
- **进入项目的产物**：`CONTEXT.md`、ADR、spec、tickets、测试结果、代码审查结论。留在聊天里的不算。
- **配置**：入口文件、Skills、Hooks 的初始投入会在每次会话里持续回报；打包成插件能防止好设置停留在少数人的「部落知识」里。
- **把资深工程师脑子里的判断程序化**：自定义 linter、工程原则让判断不再依赖某人在 review 里临时提醒。
- **领域知识**：把代码外的领域知识蒸馏进仓库，让团队判断能和代码一起 review、diff、回滚（见 Agent 原生文档（Agent-Native-Doc））。
- **输出基准**：把 Skill 的每次输出当作下一次执行的回归用例。

### 为什么在 AI 时代要特别强调
- **评估标准要换**：判断一套 Agent 工程实践值不值得长期投入，不能只看单次提速，还要看它是否持续降低规划成本、评审歧义和查找历史方案的成本。
- **资产要能被更强的模型放大**：优先建设能被下一代模型继续放大的数据和工具资产，压缩低杠杆的复杂度。
- **差距来自共享层**：Agent 工具带来的效率提升，主要来自把耐用行为放进共享层、把安全和可回滚刻进流水线、把质量门禁前移，而不是模型本身变聪明。这也是它会拉大工程师之间差距的原因。

### 实践要点
1. **趁热沉淀**：在会话结束时（例如用 Stop hook）提出入口文件的更新建议，而不是事后回忆。
2. **先人工 review 再写入**：自动持续学习有四类风险——错误模式被写入（污染）、A 项目约定串到 B 项目（跨项目）、低置信内容被当真（质量）、路径和业务信息泄露（隐私）。项目级、全局级知识都应先经人确认。
3. **给候选经验打分再晋升**：例如按观察次数给初始置信度（1–2 次 0.3 起步，11 次以上 0.85），被确认 +0.05、出现矛盾 −0.1、长期没再出现就衰减；同一模式在 2 个以上项目出现且平均置信度 ≥ 0.8 才升为全局。
4. **定期修剪**：每 3–6 个月审查一次配置；为旧模型局限打的补丁（Skill、Hook）在限制消失后会变成开销；很少触发的 Skill 删除或合并；记忆同样要修剪。
5. **新需求先回到澄清**：变更不要直接补代码，重新走澄清，把新冲突和新决策沉淀进项目知识。

## 边界与误区
- **沉淀越多越好？不是**。沉淀会膨胀成新的上下文噪音，挤占真正有用的信号（见 Context Engineering（上下文工程））。
- **缄默知识难以完整沉淀**：历史背景、低频风险、人际信息这类知识可以部分显化，但很难被完整、无损地抽象成脱离场景的固定规则。复利工程能沉淀的主要是显性知识，这是它的天花板，学徒式的现场经验仍然重要。
- **复利也会出错**：错误规则一旦固化，会在之后每次任务里被放大。所以需要验证门控和人工 review，这也是 Skill 自进化强调「验证即奖励函数」的原因。
