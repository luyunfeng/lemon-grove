# LLM Wiki 模式

> 一种用 LLM 构建个人知识库的模式：LLM 把原始资料**增量地编译**成一个持久、互相链接的 Markdown wiki，并负责长期维护；人负责投喂资料、提问和把关。它解决的是传统知识库「只收藏、不综合」和 RAG「每次查询都从头拼」的问题——知识编译一次，然后持续保持最新，而不是每次查询时重新推导。

## 要点

- **三层结构**
  - **raw**：原始资料，LLM 只读不改，是核对事实的底稿；
  - **wiki**：LLM 生成和维护的 Markdown 页面（概念、实体、对比、概览、综合等）。人读，LLM 写；
  - **schema**：一份告诉 LLM 如何组织 wiki、遵守什么约定、各操作怎么做的规则文件（Claude Code 用 CLAUDE.md，Codex 用 AGENTS.md），由人和 LLM 在使用中共同演进。
- **三个操作**

| 操作 | 做什么 |
|---|---|
| Ingest（录入） | 读资料 → 和人讨论要点 → 把知识整合进相关页面 → 补交叉链接 → 更新 index → 追加 log。一份资料可能触及 10-15 个页面 |
| Query（查询） | 先读 index 找相关页，再深入阅读、综合回答 |
| Lint（体检） | 找矛盾、过时结论、孤儿页、该有却没有的概念页、缺失的交叉链接、知识缺口 |

- **两个特殊文件**：`index.md` 按内容组织，每页一行链接加一句话；`log.md` 按时间只追加，记录录入、查询、体检等操作。
- **为什么有效**：维护知识库最累的是记账式工作——更新交叉引用、保持摘要最新、标出冲突。LLM 不会厌烦、不会忘记更新某个链接，一次能改 15 个文件。
- **适用规模**：约 100 份资料、数百个页面时，只靠 index 就能工作得很好，不需要基于 embedding 的 RAG 基础设施。

## 怎么做 / 为什么

**和 RAG 的本质区别**

- RAG 的知识在查询时临时拼装，用完即散，长期判断攒不下来；LLM Wiki 的知识在录入时就整合进页面，随资料增加而复利增长。
- 代价是录入成本更高，而且错误一旦写进页面会扩散，所以必须有 Lint。规模很大时仍可能需要搜索工具辅助。

**传统知识库为什么失效**

1. 输入持续增加，却缺少综合与修订；
2. 查询依赖临时检索，长期判断无法积累；
3. 原文、结论和变更之间没有追溯链。

**一个完整的闭环**：保存原始资料或稳定引用 → 提炼要点和影响 → 创建或更新有长期价值的知识页 → 维护链接、索引和只追加日志 → 通过 Query 复用、通过 Lint 检查质量。最重要的升级是**让每次分析都能影响后续判断**，而不是增加目录数量。

**在基本模式上常见的增强机制**

| 机制 | 作用 |
|---|---|
| 目的声明（如 `purpose.md`） | 写清知识库为什么存在、收录边界在哪 |
| 根协议 + 局部协议 | 根目录只负责路由，领域规则贴着数据放 |
| 收录门槛（Notability Gate） | 防止一次性名词长成空壳页面；和 Lint 里「被频繁提及却没有独立页」的检查方向相反，一个防滥建、一个防漏建 |
| 可追溯 | 长期结论能回到 raw 原文核验 |
| 索引与日志 | 可导航、可审计、可演进 |

**落地顺序**：文件型 wiki 先解决治理和追溯，再按需叠加搜索或向量能力。不必一次搭全，保留已有工作区，只加长期知识层、统一索引和一份 schema，搭一个最小可运行闭环。验证这套模式是否有效，关键看第一次真实的 Ingest 和随后一次只读的 Lint。

## 边界与误区

- **两种组织方式的取舍**：一种是每份资料写一页摘要，再去更新相关知识页；另一种是不留摘要页，直接把资料拆成知识点并入已有页面，只有出现新的独立知识点或新工具时才建页。前者录入快、便于回看「这份资料讲了什么」，但页面会按资料堆积，长出「汇编感」；后者页面按知识点组织，更接近「编译」的本意，代价是每次录入都要对照已有页面做合并判断。
- **查询要不要回写**：基本模式鼓励把好答案回写成新页，让探索也能沉淀；也可以让查询严格只读，值得沉淀的内容另行确认后再写入。前者积累快，后者更可控，不会因为一次问答就改动知识库。
- **误区：目录越多越好**。增加分类不等于知识在复利；关键是新资料能不能改变已有页面的结论。
- **误区：LLM 写了就对**。LLM 负责记账，不负责真伪；数字和术语要回 raw 核对，Lint 要定期跑。
- **误区：一开始就上向量库**。数百页规模内，index 加 grep 足够；过早引入检索基础设施只会增加维护面。
- 链接风格（wikilink 还是标准 Markdown 相对链接）是实现细节，但会影响可移植性：标准 Markdown 链接能被更多工具和 Agent 直接消费。
