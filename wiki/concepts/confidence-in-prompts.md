# 提示词中的置信度

**一句话**：在提示词里要求模型给每个输出标注置信度（0–1 的数字或高 / 中 / 低），等于给输出加上一个**可编程的元数据信号**：它促使模型先评估自己的知识边界，让系统按阈值决定「自动执行、等人确认、还是停下求助」，让人工只审该审的部分。但它是主观信念强度，不是概率，而且模型普遍会报高。

## 要点
置信度的六个作用：
1. **强制自我校准**：模型要先评估自己知道多少再回答，这种「元认知压力」能减少幻觉。
2. **决策路由**：高置信自动执行，中置信给建议等人确认，低置信跳过或求助。「要不要人工介入」从模糊判断变成可编程的阈值。
3. **聚焦验证资源**：从「全部审查」变成「重点审查低置信部分」。
4. **多方案排序**：高置信方案先试，低置信方案留作备选，少在不确定的路径上浪费 token。
5. **迭代收敛信号**：多轮迭代时趋势比绝对值有用——在上升说明方向对，在下降说明该换思路。
6. **可组合的元数据**：下游可以拿它做门控、告警、画校准曲线，输出从「黑盒文本」变成「可编程信号」。

## 怎么做

### 三种写法（由简到精）
- **最简版**：每个回答末尾标注「置信度：高 / 中 / 低」，低置信时说明原因。
- **阈值版**：给出 0–100% 的置信度，≥80% 直接执行，50–79% 列出建议等确认，<50% 只列思路不执行。例如：代码补全 85% 自动应用，架构方案 55% 等人确认，线上故障根因 25% 请求更多上下文。
- **分维度版**：事实置信度（对事实性知识的把握）、推理置信度（对逻辑链的把握）、执行置信度（对代码能跑通的把握）分开评估，任一维度低于 60% 时说明原因并建议如何提升。

### 校准技巧
**先让模型列出「可能出错的原因」，再打分**。先找弱点、再下结论，能明显缓解报高的倾向。这和 Skill 设计里「红旗自检」的思路一致。

### 放进系统里当信号
- **写进 Skill**：阈值版可以直接做成 Skill 里的决策路由段，高风险操作要求更高阈值，与「按风险调整自由度」的 Skill 设计原则一致。
- **分数不一定来自模型自报**：持续学习系统可以按观察统计给候选经验打分（观察次数越多初始分越高，被确认加分、出现矛盾扣分、长期不出现衰减），再用分数决定是否晋升为全局规则。这是「置信度当门控元数据」的完整实现。
- **结构化溯源页脚**：在答案后标注数据层级、新鲜度和负责人。它不是置信度，但作用相同：给人一个判断「信多少」的结构化依据。

### 模型侧的变化
能诚实表达不确定性正在成为模型能力本身：新一代模型更愿意标注不确定、更少做无根据的断言，在代码审查场景里让缺陷被漏掉的概率明显下降。「不知道时承认不知道」也是幻觉与可靠性研究的核心问题。

## 边界与误区
- **模型会报高**：大模型天生偏自信，直接问往往偏高，需要用上面的校准技巧。
- **置信度不是概率**：不要当精确概率用，只在同一模型内做相对排序和趋势判断。
- **跨模型不可比**：不同模型的置信度尺度不可直接比较，同一个数字在不同模型上含义不同。
- **有额外成本**：多用少量 token，而且需要校准。
- **阈值不是安全保证**：高置信但错误的输出——「答案错了但看起来合理」的静默失败——仍然要靠外部验证兜底。
- **内部信号不能替代外部验证**：置信度是廉价的内部信号，决定「先审哪里、要不要停下来问人」；是否真正完成要靠测试、评估器等昂贵的外部信号。让 Agent 自己判断「是不是更好」，会回到自评偏差。
