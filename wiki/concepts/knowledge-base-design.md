# 本知识库的设计与用法

> 本库是 LLM Wiki 模式的一次落地：纯 Markdown + git，由 Codex 和 Claude Code 通过全局 skill `llm-wiki` 读写。**规则只写在仓库根目录的 `AGENTS.md`**，本页只做说明，两者冲突时以 AGENTS.md 为准。

## 要点
- **按知识点组织，不按资料组织。** 每页讲清一个知识点或一个工具。新资料进来时，先拆成知识点，再去更新已有页面；只有出现新的独立知识点或新工具时才建新页，不写资料摘要页。
- **关联靠标签和实体，不靠正文链接。** 每页头部只有 `title / type / tags / entities` 四项：`tags` 取自 AGENTS.md 里的固定标签词表，`entities` 填这页涉及的工具或项目（实体页的 slug）。想找相关页面，就按标签或实体搜所有页面的头部。正文里不放站内链接，提到别的概念直接写名字；只有 `index.md` 这个目录页用链接指向各页。
- **页面只写知识本身。** 不做「谁说的、从哪看来的」归属，不挂外链，不写时间线；观点不同就写成取舍。事实在写入前回到 raw 核对，但页面上不标注。
- **skill 负责找到仓库，规则在 AGENTS.md。** skill 按线索（环境变量、常用位置、当前目录、按远端地址搜索）找本地仓库，找不到就克隆，同步后再读 AGENTS.md 并严格照做。
- **写入先确认、查询只读、只走 PR。**

## 目录结构
- `raw/`：原始资料底稿，所有文档都放在一级目录，不分类；图片放 `raw/assets/`。正文只增不改，头部只有标题，不带任何元数据；wiki 页面不链接它。
- `wiki/index.md`：知识地图，按领域分组，每页一行。`wiki/overview.md`：在学什么、掌握程度、待解问题。`wiki/log.md`：只记录写操作。
- `wiki/concepts/`：概念、方法、原则，一个知识点一页。
- `wiki/entities/`：具体工具、产品、项目，一个一页。某个实体关联了哪些页面，搜 `entities` 字段即可。
- `wiki/roadmaps/`：按阶段组织的学习与实践路线。
- `wiki/syntheses/`：只有明确要求沉淀结论时才写。
- `templates/`：页面模板；`tools/lint.py`：只读体检脚本；`tools/related.py`：按页面、标签或实体列出相关页面；`AGENTS.md`：唯一的规则文件；`CLAUDE.md` 用 `@AGENTS.md` 引入它；`skills/llm-wiki/`：全局 skill 的源文件和安装说明。

## 怎么找关联
1. 先读 `index.md`，按领域找到候选页面。
2. 再按标签或实体搜页面头部，例如找所有涉及 Claude Code 的页面、所有打了 `verification` 标签的页面；也可以用 `tools/related.py` 输入一个页面，列出标签或实体有交集的页面。具体命令写在 AGENTS.md。
3. 找到后再读正文。收录新资料时也先这样找，优先更新已有页面。

## 三条硬规则
1. **写入先确认**：炼化、收录、lint 修复、改规则时，AI 先列出要写的内容、要改的文件、分支名和 PR 标题，等我明确同意后才写。
2. **读取只读**：查询不改文件、不回写答案、不记 log、不做 git 写操作；值得沉淀的内容只提建议，由我另行发起写入。
3. **只走 PR**：`main` 通过 PR 合入。每次写入都从最新的 `origin/main` 开 `wiki/<YYYYMMDD>-<slug>` 分支，提交后推送，再用 `gh pr create --base main` 建 PR。AI 不 push main，也不合并 PR，由我在网页上审阅后合并。

## 日常用法
- 查：「查知识库：X 我记了什么？」
- 写：「炼化一下：<内容>」→ 审阅计划 → 回复「确认」→ 拿到 PR 链接 → 在网页上合并。
- 体检：「知识库体检」→ 看报告 → 需要修复时再确认。
- 新机器上安装 skill：见 `skills/llm-wiki/INSTALL.md`。

## 怎么用好它
- 每读完一篇值得记的资料就炼化一次：先审 AI 列出的「要更新哪些知识点」，再审 PR。
- 学习中的问题先用「查知识库」提问；值得沉淀的结论再说「炼化一下」。
- 定期跑 lint，关注标签是否都在词表里、实体是否都有对应页面。
- 标签不够用时，先把新标签加进词表，再给页面使用。
- 规模变大后，再评估是否需要本地搜索工具，或导出为 Open Knowledge Format。
