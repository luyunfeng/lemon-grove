# Context Engineering 与工具执行独立化

## 核心观点

- Context Engineering 的关键不是“把更多内容塞进上下文”，而是持续找到最小但高信号的输入集合。

## 记录到的问题

- 上下文本质上是每次调用模型时注入的 token 集合，而 token 是边际收益递减的有限资源。
- 静态 context 会随着工具、文档和规则增加而膨胀。
- 动态 context 也会在 ReAct 循环里不断变脏，尤其是长日志、编译输出、网页正文和大文件内容。
- 当上下文越来越长、越来越杂时，模型对真正关键信息的关注反而会下降。

## 可行方向

- 让长日志、网页正文、大文件和测试输出优先落到外部存储或索引层。
- 主上下文只保留压缩后的摘要、结论或可检索句柄。
- 把“工具执行”尽可能从主推理上下文里隔离出去，降低噪音密度。

## 我的判断

- 真正值得建设的不是“无限加长上下文”，而是让高信号信息以更低噪音进入主上下文的机制。
- 这件事和工具设计、检索策略、日志治理其实是同一个问题的不同侧面。
