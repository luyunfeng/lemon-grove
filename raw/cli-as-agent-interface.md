# CLI 才是 Agent 的最佳工具接口

## 核心观点

- 对大模型 Agent 来说，最好用的工具接口往往不是新的协议层，而是已经成熟的 Unix CLI。

## 为什么是 CLI

- CLI 的适配成本极低，现有工程能力天然就能接入。
- 训练语料足够丰富，模型对命令式交互的熟悉度更高。
- 组合能力强，可以通过管道、脚本和小命令自然拼装复杂流程。
- 调试过程透明，人和模型执行同样命令时更容易对齐结果。
- CLI 很适合做渐进式披露，只返回当前步骤真正需要的信息。

## 我的判断

- 工程投入应优先放在 CLI 的设计和质量上，把它当作 Agent 能力层的基础接口。
- Agent 友好的 CLI 最好满足几个特征：非交互、结构化输出、幂等、可组合、便于局部调用。
- MCP 更适合看作 CLI 之上的 thin adapter，而不是完全独立于 CLI 的另一套能力层。
- 很多复杂单体工具，最后更适合拆成一组 CLI，再由 Skill 编排。

## 延伸想法

- 真正值得建设的不是“给模型更多工具”，而是“给模型更容易理解和调用的工具”。
- 如果一个能力不能自然地被拆成清晰的小命令，它通常也不容易被模型稳定使用。
