# 如何更科学、方向可控地实现 Skill 的"自进化"？

来源：[飞樰 @ 微信公众号](https://mp.weixin.qq.com/s/2Cq0QR3vcKlMHkI0XyYYrw) · 学习日期：2026-06-09 

## 核心问题

  * **过拟合** ：为迎合 badcase 把个例补进去，Skill 越来越"特化"
  * **质量飘忽** ：越优化越差，企业级场景不敢直接 Online 自进化
  * **缺乏验证** ：没有"奖励函数"，进化方向不可控

## 三种里程碑式方案对比

### Trace2Skill

阿里千问团队

归纳法

聚合大量 Agent 轨迹，通过**并行分析 + 层次合并** 提取通用 Skill。核心思路是"从经验中归纳规律"。

验证方式仅为编程式格式校验，**无显式效果验证** 。

### EvoSkill

Sentient Labs

自验证自然选择

构建**执行-提案-构建-验证** 闭环。维护"前沿集合"，只有验证集得分超过最弱者的 Skill 才能保留。

失败驱动进化，累计反馈历史 H 作为"动量"。

### SkillOpt

微软 + 高校

模型训练对标

将 Skill 优化**对标为模型训练** ，引入学习率、动量、验证门控等约束。

每步 ≤Lt 条有界原子编辑，"严格大于当前最优"才接受更新。

### Trace2Skill 关键数据

122B 参数 LLM 生成 200 条 50+ 轮次轨迹，"不到两个小时"完成聚合归纳。

### SkillOpt 关键数据

Batch Size = 40，Minibatch = 8，最终产物 300-2000 Tokens。

## 典型案例：阿里云服务 "ECS 无法远程连接"

单工单难以抽象通用方案。大量聚合后发现真正的"最大公约数"：

  * CPU / 内存跑高
  * 磁盘写满
  * 端口不通
  * 安全组拦截

## 演进趋势

> "从'经验主义'走向'科学工程'，验证机制是效果可控的关键。" 

Agent 产生轨迹 → 自动化验证给出即时反馈 → 根据反馈快速调整 Skill → 新 Skill 再次进入验证循环
