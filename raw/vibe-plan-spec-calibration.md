# Vibe Coding、Plan 与 Spec 的协作校准差异

## 核心观点

- 三者的核心差异不在“谁更高级”，而在于把多少校准机会前置到了执行之前。

## 记录到的判断

- Vibe Coding 最轻，用户只说目标，Agent 自主决定方案、拆解任务并写代码。
- Plan 在执行前增加一次方向校准，先明确需求和方案，再开始执行。
- Spec 最重，把需求、设计、任务拆解都纳入“用户输入 + Agent 执行 + 用户审查”的循环。

## 我的理解

- 任务越复杂、越长期，越值得为额外校准支付流程成本。
- 小需求使用完整 Spec 的仪式成本偏高，不一定划算。
- Plan 的价值通常不在文档本身，而在执行前那次方向校准。
- 对于需求边界还在收敛、但实现成本已经不低的任务，Plan 往往是投入产出比最高的选择。
