# 泳道图定稿画法

v1.1.0 的优先视觉参考是用户认可的 [记忆读写泳道图](../assets/swimlane/memory-flow.svg)，其 [结构](../assets/swimlane/memory-flow.json) 可用于查看泳道、节点和关系定义。简单单向交接仍可参考 [基础样例](../assets/swimlane/example.svg)。

## 从这张图复用什么

- **横向泳道分职责，横向推进分阶段。** 左侧用饱和色道头，整条泳道铺同色浅底；顶部阶段栏用中性灰，避免让阶段色与责任色竞争。阶段数和泳道数由任务决定，不固定为本例的五阶段、四泳道。
- **步骤跟随责任色。** 动作用同色标题带＋浅底矩形，条件判断用同色菱形；字号和形状区分层级，颜色只表示职责归属。正文保持深色，浅橙区域优先用深字。
- **框归属于真正执行者。** 决策与读写请求放在发起者泳道；若包含文件、数据库或队列等资源泳道，明确标成“被读写的资源”，在其中呈现数据/读出结果/持久化结果，不让资源看起来会自行决策。
- **箭头写清交接对象。** 用“请求资料”“返回结果”“保存索引”等动词说明流向；判断出口直接标明“是：执行什么”“否：去哪里”，不只靠箭头颜色暗示条件。
- **主链与回路分通道。** 常规动作/数据交接用实线，同一轮继续或重试用长虚线；只有内容确实跨轮次/会话时才增加点线并明确起点与边界。每张图的图例与实际线型一致，不套用时序图的返回线惯例。
- **未来复用与本轮继续分开。** 有跨轮次状态时，画清继续本轮和重新开始的不同路径；依赖关系按事实连，不把“本轮产生新增”误画成“下一轮能开始”的必要条件。
- **按密度分配空间。** 步骤多的泳道可以更高；给跨泳道连线和回路预留走廊。等价步骤保持相近尺度，长说明放到底部简短注释。关键交点应无歧义；线穿框、压字或容易被当成合流时调整路由。

## 迁移到新内容

先确定参与者/资源、阶段、条件和回路，再套用以上视觉语法。复用配色和排版方法，不复用 Claude Code 的角色名称、节点数、业务结论或坐标。用户指定图型时遵从其要求；其余技术图继续使用各自语法。

这个参考图的业务内容是一次研究快照，相关产品机制可能变化；它是绘图参考，不替代新任务中的事实核验。

## 发布前核对

节点落在正确泳道；主动决策与被动资源分清；条件路径覆盖输入要求；读写和回路方向可跟踪。原生文本检查覆盖标题、正文、边标签及重要脚注/路径；再查看飞书回读预览。几何检查通过不能替代逻辑与目视检查。
