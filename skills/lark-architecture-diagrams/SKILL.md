# 飞书技术图：配色与布局语法

**v1.1.0 已定稿。** 用户已确认 [标准样例](references/examples.md) 的视觉风格，并进一步选定“Claude Code 记忆流程”泳道图作为涉及条件分支与回路时的优先参考。之后在绘图请求中只需提供逻辑，直接按本风格完成，不再要求选择风格或图型。

固定的是白底、蓝紫青橙语义色族、饱和标题带、浅色分区、深色文字、图型专属布局和连线语法。角色名称、实体数量、坐标、画布尺寸与分组映射随输入调整。颜色丰富度来自语义分组，业务复杂度由输入决定。

## 只给逻辑时的默认行为

- 描述谁负责什么、步骤如何交接：选泳道图；描述实体、字段、主外键和基数：选 ER 图；描述谁调用谁以及先后、返回和分支：选交互时序图；描述模块、分层、依赖和边界：选架构图。
- 混合描述先选最能回答主问题的一张图，必要时增加一张互补细图，不自动产出整套样例。
- 用户未另定交付形式时沿用可编辑飞书画板，指定文档时写入该文档；仅要本地 SVG/PNG 等时遵从其要求。单纯讨论逻辑不会自动创建飞书产物。
- 不重复询问配色、字号或布局偏好。只有会改变关系正确性的信息缺失时才澄清，例如未明确的 ER 基数；低影响的排版细节自行决定。

## 选图型，再定义视觉映射

先读 [图型与布局](references/logic.md) 和 [配色规则](references/style.md)。确定画泳道图时，再读 [泳道定稿画法](references/swimlane.md)，按本次认可样例安排职责、阶段与回路。不要把所有输入套成架构卡片。

| 图型 | 颜色优先编码 | 布局必须表达 |
|---|---|---|
| 架构图 | 业务域、职责或部署归属，选一种主维度 | 分层、包含、依赖、边界 |
| 泳道图 | 角色、团队或系统责任 | 步骤归属、推进方向、跨泳道交接 |
| ER 图 | 实体所属领域 | 字段、PK/FK、关系、可选性与基数 |
| 交互/时序图 | 参与方 | 生命线、时间、消息方向、返回和分支 |

1. 提取用户明确提供的对象与关系，标记未知项。读参考图时同时学习颜色含义、视觉层级、空间组织和线型，不只取色值。
2. 给当前图定义一份小型 `visual_map`：颜色表示什么，容器表示什么，横轴/纵轴表示什么，连线表示什么。一个颜色维度保持一致；状态、主次等其他维度优先用标签、线型和灰阶。
3. 在任务目录保存 `architecture.json`（兼容文件名，内容可为任意技术图），结构见 [结构约定](references/structure.md)。按图型补充 lanes、fields、cardinality、message_order 等语义。内容不确定时标明“示例/假设”，不将示例数据库模型冒充真实系统。
4. 默认用已验证的 SVG 路径保持定稿的配色与逐元素编辑能力，并遵循对应图型语法；用户指定 Mermaid/PlantUML 时从其要求，交付前核对样式差异。复杂 SVG 按 lark-whiteboard 流程处理。
5. 普通请求默认一版；需要比较才做多版。验证跨图型通用性时可以使用同一场景的泳道、ER、交互样例。不同图型解释的问题不同，不强制节点数和连线数相同。

## 绘图与验收

SVG 的每个业务节点标记 `data-node-id`，每条关系标记 `data-edge-id/data-source/data-target`。文字保留 `<text>`，图标变换隔离到独立 g。使用 [偏好状态](assets/preference.json)；[示例资源说明](references/examples.md)解释示例适用范围。

```sh
python3 <skill>/scripts/diagram.py check --spec architecture.json --svg diagram.svg --out checks
```

脚本检查节点与文字覆盖、SVG兼容性、画板转换后的溢出与重叠，以及业务文字是否保留为可编辑节点。发布使用结果中的 `publish_svg`（`checks/diagram.svg`），保留原始源文件。需要 python3、npx 和 `@larksuite/whiteboard-cli@0.2.13`。

**查看 PNG 并做图型验收**：泳道节点是否归属正确、ER主外键与两端基数是否一致、交互顺序和请求/响应是否准确。ER关系不要用执行箭头表达；时序返回不要混同任务完成。几何检查通过不代表语义正确。

确认在颜色之外也能靠标题、标签、线型理解关系。主要文字清晰，连线不穿字；不为增加颜色数而随机分色，不为维持模板而漏掉关系。

## 飞书交付与迭代

读取 lark-doc、lark-whiteboard 及相应参考。用户要求放到飞书已授权创建对应产物，不重复问发布确认。配置见 [飞书接入](references/lark.md)。文档正文由主 Agent 维护，复杂图按 lark-doc 要求交给独立子 Agent，目录/画板相互隔离。

新空画板可以使用：

```sh
python3 <skill>/scripts/diagram.py publish --svg checks/diagram.svg --board <token> --profile <profile> --expected-app-id <app-id> --state publication.json
```

助手拒绝覆盖已有画板。发布后回读 raw 核对全部关键文字，并导出远端 PNG 目测。图标可能保留为图片；未验证的连接器端口绑定不作承诺。缺权限时按实际错误申请最少 scope，先完成不依赖授权的工作。

迭代默认保留已有版本，明确要求原位修改时先核对远端手改。交付图、链接、验证状态和实际局限。常规绘图不改变本 skill 的定稿风格；用户明确要求调整通用风格时再更新样例和版本。知识库查询保持只读，画图不会自动授权知识库写入。
