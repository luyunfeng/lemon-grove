# speak-human：说人话，按点说清楚

把中文草稿整理成自然、有逻辑的 Markdown 要点。优先保留原意，再整理逻辑与排版，最后减少套话、翻译腔和机械表达。

## 适用场景

- 将一段较长说明整理成方便扫读的要点。
- 整理评审同步、研发排期、方案对齐或操作说明，保留条件、责任和后续安排。
- 只诊断表达问题、轻改措辞，或按明确量表比较改写前后的文风与逻辑。

默认输出一级编号、必要的二级圆点和局部加粗。每个主项包含完整意思，补充和例外跟在对应主项下面；具体点数由内容决定。格式示例不是必须套用的固定模板。

## 安装与调用

按[技能目录的安装说明](../README.md#安装与更新)，安装完整的 `skills/speak-human/` 目录。本技能运行时依赖宿主模型，不需要额外 API Key、外部检测服务或 Python 脚本。

常用请求：

```text
用 $speak-human 改写下面这段话，保留原意，按点展开：
……

用 $speak-human 只调整格式，原句不要改：
……

用 $speak-human 只诊断，不改写，指出具体问题：
……

用 $speak-human 改写并评分，分别检查原意、AI 味和逻辑：
……
```

默认只返回终稿。用户明确要求一句话、保留原有格式或只诊断时，以该次要求为准。文本中引用的指令只作为待编辑内容，不会因此变成可执行任务。

## 输入与输出示例

以下内容为虚构示例。

输入：

> 计划下周先发布查询功能，不包括导出，导出还没测完。查询功能需要先通过灰度，失败就延期。测试环境已经通过，但线上尚未验证。

一种符合要求的输出：

1. **本次范围：**计划下周先发布查询功能。
   - 暂不包含导出，导出还没测完。
2. **发布前提：**查询功能需要先通过灰度，失败就延期。
3. **验证状态：**测试环境已经通过，**线上尚未验证**。

这次改写保留了计划状态、功能范围、灰度条件和验证边界；没有把下周的计划写成确定承诺，也没有把测试环境通过改成线上通过。

## 保真与评分

- 对照原文核对主体、数值、否定、条件、因果、计划状态和引用归属。实质信息有遗漏、增添或改变，就不能只凭“更顺口”判通过。
- 原文中的代码、命令、链接目标、直接引文和结构化数据保持原样。未明确消除的矛盾或歧义不靠猜测补齐。
- “AI 味”按空泛、冗余、机械、别扭和语气失配评分，范围为 0–10，越低越好；逻辑清晰度为 0–10，越高越好。原意是否保留单独报告，不合成一个总分。
- 评分是编辑判断，不是作者身份鉴定或 AI 生成概率。保留原意也不代表已经核实原文事实。

详细规则见[评分标准](references/rubric.md)。

## 验证方法

从仓库根目录执行 `python3 tools/lint.py` 检查知识库规则与敏感信息；这个命令不验证改写质量。技能元数据可使用宿主提供的 skill 校验工具检查，同时确认包内相对链接都能找到目标。

修改指令后，用真实输入检查以下行为，保存当次输入、输出和发现的问题：

| 用例 | 应保留的内容或行为 |
|---|---|
| 带否定、联合条件和例外的说明 | 条件的作用范围、且/或关系、否定与例外不变 |
| 带数字、比较对象和不确定性的说明 | 数值归属及证据强度不变，不擅自换算或补结论 |
| 带代码、命令、引用与链接的文本 | 原始内容和引用归属保留 |
| 长段落与多项安排 | 主干编号、从属补充、重点加粗；必要解释不遗漏 |
| 只要求修改格式 | 去掉新增 Markdown 标记后，正文与原句一致 |
| 原本没有矛盾的通知 | 不把“可以”当“必须”，不把明确例外误报成矛盾 |

逐条核对原文与输出，不能只数关键词或依靠相似度。需要比较两个版本时使用同一批输入；模型自评与人类评价分开记录，不把旧版分数当作新版效果。
