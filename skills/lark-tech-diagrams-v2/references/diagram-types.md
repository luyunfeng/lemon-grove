# 按问题选图型

| 要解释的问题 | diagram_type | 保留的语法 |
|---|---|---|
| 谁使用系统、依赖哪些外部系统 | c4_context | 单一系统焦点，人物、外部系统和边界 |
| 一个系统的应用与数据容器 | c4_container | 容器职责、已给定技术、系统边界 |
| 一个容器内部组件 | c4_component | 组件职责、容器边界、外部容器 |
| 软件层次与职责依赖 | layered_architecture | 层顺序、模块归属、调用方向 |
| 服务运行在哪里 | deployment | 实例、运行区、制品与协议 |
| 设备和区域如何连通 | network_topology | 路由/交换/防火墙/服务/存储、区域与方向 |
| 判断与处理步骤 | flowchart | 动作、条件、结果出口、回路 |
| 谁负责每一步 | swimlane | 责任泳道、归属、条件、交接与回路 |
| 谁先调用谁、何时返回 | sequence | 生命线、顺序、同步/异步/返回与分支 |
| 对象状态如何改变 | state | 初始/最终状态、事件、守卫与效果 |
| 活动如何并行和汇合 | activity | 初始/终止、决策/merge、fork/join |
| 数据实体如何关联 | er | 字段、PK/FK、双端基数和可选性 |
| 类型及对象关系 | class | 属性/方法、继承/实现、聚合/组合、关联/依赖 |
| 数据经过哪些变换 | dataflow | 外部实体、处理、存储、有数据名的流 |
| 模块依赖谁 | dependency | 依赖方指向被依赖方、领域与边界 |
| 发布、订阅和失败投递 | event_flow | 发布者、主题、独立订阅、确认和死信 |

根据用户要回答的问题选择，不要求用户知道图型名称。多个视角分别绘制并保持命名对应；数据关系不能当流程，类继承不能当调用。
