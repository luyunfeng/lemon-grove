# 工具交接

绘图Skill负责“表达什么、布局和色彩如何表达、产物是否正确”。工具负责“如何创建目标资源、转换和传输”。不要复制工具的API、授权或重试实现到本包。

| 需要的能力 | 使用现有能力 |
|---|---|
| 创建/查找文档、放置空画板 | lark-doc，按其当前文档操作说明 |
| SVG目标转换、更新画板、导出PNG、读取原生节点 | lark-whiteboard / 官方whiteboard-cli / lark-cli |
| 当前用户身份、授权、权限异常 | lark-shared及当前用户配置 |
| 云盘上传、移动、父目录与权限 | lark-drive，仅在任务需要时使用 |

读取当前环境中相应Skill，按其参数调用，不依赖本包复制的旧API示例或个人路径。若没有这些Skill但有官方CLI，先查该CLI的help；不要猜命令或目标账号。

交接包包含diagram.svg、input.json、layout.json、validation.json、result.json。result.handoff给出SVG格式、路径与sha256。把它作为**已有SVG**交给目标工具；不是要求目标工具重新创作同类图。遇到工具的“从零绘图”路由表，应使用其已有SVG输入路径，避免切换Mermaid/DSL后改变风格。

目标验收：用官方工具检查并预览这个SVG；写入后由同一工具导出真实PNG并读取文字。核对节点、关系、文字及次数，实际看图确认没丢字/遮挡/错误线型。必要的离线文字比对可用validate.native_text_check，它只检查导出的内容，不调用服务端。主文字原生可编辑与连接器拖动绑定是两项不同能力，未测试后者就不承诺。

参考兼容版本是whiteboard-cli 0.2.13；环境使用其他版本时，先用包内参考SVG做转换/文字/视觉检查，不静默改绘图规范来迁就未知转换行为。服务端导出可能有方形外围留白，检查实际内容区域。

用户已经给出目标文档/画板时沿用其目标。缺权限、工具或目标信息时保留本地产物并报告具体缺口，由所属工具处理；绘图成功不代表云端交付完成。

离线文字检查输入示例：`native_text_check(svg_path, [{"text": {"text": "节点名称"}}])`。第二参数是节点列表，由调用方按当前工具响应解包，不能直接传整个响应信封。检查按每段文字去空白后计数；若转换工具改变了文本分段，需先确认分段差异并核对实际显示，不能据此直接断言丢字。响应适配继续由平台工具/调用方承担，本包不实现服务端API。
