# 迭代验证

仅在用户要求改进Skill时启动。轮数由本次任务明确约定，不把某次实验的10–20轮写成所有用户的固定义务。

1. 在包外复制候选，冻结指令、模板、代码、色板和字体hash。记录假设及验收门槛，稳定版先保留。
2. 两类验证分别做：同输入的16类参考SVG应一致；新上下文子Agent仅凭候选包和新逻辑生成陌生图。不提供旧对话、旧分数、预期答案或修复提示。依赖/工具是正常运行条件，不能冒称空白机器免安装。
3. 另一独立Agent实际看新图和相应demo，对照原始需求检查事实、方向、符号、责任/基数、颜色语义、层级、间距与可读性。机器检查不代替看图。评分说明见review-instructions.txt。
4. 根据具体失败修改；再跑受影响的新任务及16类参考回归。长标签、复杂拓扑和跨业务输入可用assets/regressions。保留失败及复测，不抹分、不删关系或降低门槛求通过。
5. 需要飞书集成验证时，把SVG交给lark-whiteboard/lark-doc等现有能力，实际回读核验；不得为测试再把文档、上传或授权代码塞回绘图包。
6. 完成用户约定轮数、无严重语义/可读性缺陷、参考风格无无意漂移后，再打包和升级。检查旧安装未被并发修改，备份可恢复版本。实验记录留在包外，包内只加入未来任务确实需要的规则、示例或检查。

改变视觉设计而导致参考SVG变化时，必须有明确改进依据和新图独立评审；重新冻结参考，不能只刷新hash掩盖回归。交付说明区分已测操作系统/依赖、未测平台和云端能力。
